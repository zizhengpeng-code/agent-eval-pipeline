# 专家级 Agent 任务构建与公平盲测方法论

本文档总结了这套管线背后的核心工程原则：如何从真实专业场景出发，构造**可自动验证、抗泄题、具备区分度**的复杂文件处理任务，并以统一口径完成多模型公平盲测。

---

## 一、核心设计原则

1. **证据闭环，不凭空编题**
   - 每个考点都必须能回溯到真实业务流程或公开操作规范；不考察模棱两可、缺乏唯一判定标准的主观题。
2. **完全虚构化，杜绝记忆作弊**
   - 公司名、人名、合同号、具体金额全部重构虚构，但前后明细账、汇总表、合同条款、邮件沟通之间保持严格的勾稽一致性。
3. **材料只给事实，题面不泄解法**
   - `reference_files/` 中只放原始业务事实（含合理噪声和跨文件冲突），绝不出现最终结论。
   - `task/task.md` 以真实同事交代工作的口吻书写，不替模型拆分解题步骤、不提示具体法规条文或公式写法。
4. **上下游耦合与二元评分点**
   - 高质量任务应包含跨文件核对（如 PDF 合同/函件 vs Excel 明细表）以及上下游联动计算（上游差错会传导至下游报表）。
   - `rubric` 采用二元客观判定（达标得满分，否则 0 分），每条只评一件事；对存在上下游依赖的评分项，注明“上游已失分时按答题人自身上游结果复核”，避免同一错误重复扣分。
   - 配套独立扣分项（如伪造不存在的依据、出现循环引用或大面积公式错误等）。

## 二、标准任务包与四道门禁（Gate 1 – Gate 4）

### 任务包目录约定

```text
任务包_<编号>_<名称>/
├── task/
│   └── task.md                # 任务说明（仅投放给被测模型）
├── reference_files/           # 多格式参考材料（.xlsx/.csv/.docx/.pdf/.txt）
├── ground_truth/              # 标准答案交付物（绝不投放给被测模型）
└── rubric/
    ├── rubric.xlsx            # 评分表（含动态合计公式）
    └── rubric.csv             # 结构化评分表
```

### 四道自动化门禁

| 门禁 | 阶段 | 核心检查项 |
| --- | --- | --- |
| **Gate 1** | 任务包交付前 | 目录结构完整性、多格式材料可读性、`.xlsx`/`.docx`/`.pdf` 封装合法性 |
| **Gate 2** | 任务包冻结前 | Rubric 分值精确合计 100 分、无模板占位符、GT Excel 全表 AST 重算 0 错误且 100% 匹配缓存值 |
| **Freeze** | 盲测前 | 对 `task/task.md` 与全部 `reference_files/*` 生成 SHA-256 冻结指纹，盲测前强校验 |
| **Gate 3 & 4** | 盲测评测后 | 校验评测报告完整性、被测产物（或超时缺失说明）完整落盘、Excel 重算结果与评分明细一致 |

---

## 三、公平盲测的工程纪律

1. **物理目录隔离**：运行器在 git 仓库之外新建临时隔离目录，仅拷贝 `task/task.md` 与 `reference_files/*`，并二次比对 SHA-256 与冻结指纹。
2. **中性一致提示词**：所有被测模型使用完全相同的 `USER_PROMPT`，不针对单一模型做额外提示词调优。
3. **强制审计与全量落盘**：
   - 无论正常退出、报错还是超时（`rc=124`），均在 `finally` 阶段将工作区完整归档；
   - 自动扫描工具调用轨迹是否触碰 `rubric`、`ground_truth`、`curl`、`wget` 等敏感词；
   - 自动对模型输出的 `.xlsx` 执行离线 AST 公式重算，记录真实公式数、错误数、循环引用数及缓存不一致数。
4. **如实记录部分交付**：当模型在超时上限内仅完成部分文件时，严禁人工补齐或伪造缺失文件，应如实归档已有产物并附 `缺失交付物说明.txt`，按客观 Rubric 打分。
